# Engineering notes from implementation (GPU-milestone flags, consensus pins)

Collected from implementer reports; review before the first rented-node run.

- **[C.core.engine.inner]** AdamW parity is pinned against torch 2.13's single-tensor non-capturable path (lerp_ first moment, python-float bias corrections, addcdiv_). A torch major bump that changes that kernel sequence is a consensus change for window replay — pin torch in the container.
- **[C.core.engine.inner]** Autocast caveat for GPU milestone 1: InnerLoop enables torch.autocast(cuda, bf16) per spec, but mok_core.model.router.Router.proj is an nn.Linear — under autocast its matmul may run bf16 despite the fp32 input cast, weakening the 'fp32 router' guarantee. Recommend an `with torch.autocast(enabled=False)` guard inside Router.forward (outside my allowed paths, so not changed here).
- **[C.core.engine.inner]** Grad-norm clip spans all ranks: expert-local squared sums travel through a second fixed collective (1-element fp32 all_reduce) so EP-sharded grads count in the global norm. This is collective #2 of exactly 2 per inner step; window_runner/comm implementors must call reductions in lockstep on every rank.
- **[C.core.engine.inner]** Capacity util uses the PROTOCOL EP geometry from cfg.model (not the model instance's ep_size), so a validator running the ep=1 reference replica computes the same util a miner sees on hardware. On a RunConfig whose model literally has ep_size=1 the metric degenerates to 1/capacity_multiplier by construction.
- **[C.core.engine.inner]** null_round runs the complete hot path (forward/backward/reductions/clip/MoeHealth) and skips only Zero1Adam.step — balance_bias buffers still evolve, so a warmup window must discard or pseudo_grad-restore θ afterwards (test pins: only balance_bias digests change).
- **[C.core.engine.inner]** accum_at can return 0 if a config sets accum_ramp_start=0; InnerLoop clamps per-step accum into [1, plan.grad_accum] (plan.grad_accum is the schedule ceiling during the ramp).
- **[C.core.engine.inner]** Test-infra note: this box has 16 cores and torch intra-op parallelism makes tiny-tensor ops ~30x slower (12.9s vs 0.41s for a tiny model init). My 4 test modules pin torch.set_num_threads(1) via a module-scoped autouse fixture and restore the previous value afterwards; consider the same for the pre-existing model tests (round-A files untouched per ownership rules).
- **[C.core.engine.inner]** flat_grad_all_reduce with world_size=1 is bitwise lossless (fp32 staging of bf16 grads, divide by 1), so the single-process/CPU path is byte-identical to the multi-rank code path — property-tested over 1M values incl. inf/nan.
- **[C.core.engine.inner]** CpuSnapshot.take(pin=True) on a CUDA-less host raises torch's pin-allocator RuntimeError by design; the pin=None default resolves to torch.cuda.is_available().
- **[C.core.engine.inner]** TorchDistComm treats src_rank as group-relative (translated via dist.get_global_rank) to match the protocol's group-relative round-robin bucketing; sanity-tested against a real 1-rank gloo group.
- **[C.core.engine.inner]** Integration-test synthetic data: a 4-token cycle (3->5->7->11) with per-shard phase shift plus one unique constant row per shard — keeps all 8 shard files byte-distinct (distinct Merkle leaves) while being learnable in 3 inner steps (entry 6.09 -> final ~1.6 at const lr 0.02).
- **[C.core.engine.inner]** Scratch LR sweep results (2-layer H=512 model, 3 steps x 2 accum): final loss 1.57/1.52/1.60/2.11 at lr 0.005/0.01/0.02/0.05, roots bitwise equal at every LR — the gate is not LR-sensitive.

## Stage-3 memory rule (from MoE-literature audit §5)

MoK's fused backward saves per-layer fp8 context sized by `macrobatch_size`
(x_t, gate, up, hidden_t + scales). At Stage-3 shapes (H=6144, 36 layers) the
default macrobatch 131072 costs ~50 GB/GPU of saved context on top of the
~234 GB budget. Rule: budget Stage 3 with macrobatch 65536 first (context
halves; backward replays more), and only raise it if measured headroom allows.
Measure, don't estimate, at the Stage-3 calibration rehearsal.
